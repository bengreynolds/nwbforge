# Hybrid Workflow Baseline

Purpose: capture sessions that mix supported and custom inputs.

Current baseline:
- Hybrid sessions can combine supported and custom sources in one desktop flow
- The current descriptor is a bootstrap path that exercises the shared pipeline
- Shared grouping, normalization, mapping, and review state are used for both source types

Constraints:
- Hybrid support should remain a workflow over shared contracts, not a separate product
- The descriptor is compatibility and testing state, not the primary ingest model

Next step:
- Grow hybrid handling through the same direct-ingest and metadata-review contracts used elsewhere
